# OPEN WRITER

## Complete Autonomous Product Engineering Master Specification

### Mission

Build a production-quality, open-source, independent writing platform inspired by the publicly observable functionality and workflows of Novlr, while substantially extending it into a local-first writing operating environment with:

* Windows desktop application
* fully functional web application
* offline-first operation
* optional cloud synchronization
* self-hosting
* collaboration
* author websites and publishing
* structured story intelligence
* autonomous AI agent
* deterministic tool system
* browser automation
* secure sandbox execution
* OpenSandbox integration
* optional Kata / Firecracker / gVisor isolation
* SUPERrr-FREE design intelligence and QA
* Z.ai / GLM support
* Ollama
* LM Studio
* OpenAI-compatible providers
* MCP
* CLI
* open project format
* complete import/export
* real version history
* real Windows `.exe` and installer artifacts

The final product must be independently usable without Z.ai, without the original Novlr service, without an internet connection for core writing functionality, and without mandatory AI.

---

# 0. ABSOLUTE PRODUCT PRINCIPLES

These principles are non-negotiable.

## 0.1 Do not build a demo

Do not produce:

* fake buttons
* fake analytics
* fake synchronization
* fake AI
* fake collaboration
* fake version history
* mock export
* mock sandboxing
* placeholder pages
* hard-coded sample data in production paths

A feature is not complete because a UI exists.

---

## 0.2 Never confuse generated code with working software

Every major feature must be:

* implemented
* integrated
* persisted
* tested
* verified
* documented

---

## 0.3 Never claim completion without evidence

Use explicit statuses:

```text
NOT STARTED
IN PROGRESS
IMPLEMENTED
TESTED
VERIFIED
NOT VERIFIED
BLOCKED
DEFERRED
```

Never replace:

```text
NOT VERIFIED
```

with:

```text
PASS
```

---

## 0.4 Never guess when evidence is available

Research first.

Inspect the repository.

Inspect the environment.

Inspect available skills.

Inspect current public documentation.

Use actual browser behavior where appropriate.

Do not invent what Novlr, Z.ai, OpenSandbox, Tauri, Kata, or any dependency does.

---

## 0.5 Preserve working code

The current repository already contains a working initial vertical slice.

Do not rewrite functioning components simply because a different implementation is aesthetically preferable.

First understand the existing implementation.

Refactor only when justified.
